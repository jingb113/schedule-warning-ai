# 工期预警管控系统（AI 版）

面向工程项目的**工期偏差自动预警**工具：读取「总进度计划 + 每日工程日报」两张 Excel，自动比对主任务与子任务的计划/实际进度，输出红黄绿三级预警报表，并可一键把预警结论通过邮件推送给项目团队。

命令行版额外集成**大模型分析**：把当日结构化数据交给 LLM（OpenAI 兼容接口），自动生成「问题诊断 + 纠偏建议」，省掉人工写分析的时间；不配置大模型时自动回退到纯规则分析，功能照常可用。

---

## 功能特性

- **主任务比对**：日报「进行台账」1.1 节总体行 vs 总进度计划，计算计划应完成%、实际完成%、偏差与偏差天数
- **子任务明细**：日报 1.2~1.6 全部分类子任务，按时间偏差判红/黄/绿
- **施工队分区对比**：按分区（A/B/C/D…）统计各施工队的到期履约率、施工强度中位数等可比口径
- **关键节点提醒**：未来半个月内的关键节点、已过期节点单独标记
- **未来一周计划启动任务**：提前预警即将开工但可能受前置条件制约的任务
- **大模型 AI 分析**（命令行版）：自动产出问题清单与可执行建议
- **邮件推送**：生成 HTML 预警日报，正文 + 报表附件一起发送
- **Flask Web 版**：浏览器上传文件、在线查看结果，适合不熟悉命令行的同事

## 目录结构

```
.
├── schedule_warning.py        # 命令行主程序（含大模型 AI 分析）
├── run_warning.bat            # Windows 一键运行命令行版
├── requirements.txt           # Python 依赖
├── .env.example               # 环境变量模板（复制为 .env 后填写）
├── .gitignore
├── master_plan/               # 放总进度计划 xlsx（输入）
├── key_nodes/                 # 放关键节点汇总 xlsx（输入，可选）
├── daily_reports/             # 放每日工程日报 xlsx（输入）
├── warning_output/            # 程序输出的报表与邮件预览（自动生成）
└── web/                       # Flask Web 版（规则分析，不含大模型）
    ├── app.py                 # Flask 后端
    ├── schedule_warning_core.py  # 核心比对逻辑模块
    ├── templates/index.html   # 前端页面
    └── run_web.bat            # Windows 一键启动 Web 服务
```

## 环境要求

- Python 3.8+
- 依赖见 `requirements.txt`

```bash
pip install -r requirements.txt
```

命令行版仅用到 `openpyxl` + Python 标准库；Web 版额外需要 `flask`。

## 快速开始

### 1. 准备输入文件

把三类 Excel 放到对应目录（文件名可自定义）：

| 目录 | 内容 | 是否必需 |
|------|------|---------|
| `master_plan/` | 项目总进度计划表 | 必需 |
| `daily_reports/` | 每日工程日报（文件名含日期，如 `工程日报 2026.10.11.xlsx`） | 必需 |
| `key_nodes/` | 关键节点汇总表 | 可选 |

> 程序默认在 `daily_reports/` 里按「昨天」的日期自动定位日报文件；找不到则回退到目录内最新的一份。
> 日报文件名需包含 `DAILY_FILE_KEYWORDS`（默认 `工程日报`）里的关键词，可按需修改。

### 2. 配置环境变量

复制 `.env.example` 为 `.env`（或直接设置系统环境变量），按需填写：

- **必填**（发邮件时）：`SMTP_USER`、`SMTP_PASS`（邮箱授权码，非登录密码）、`EMAIL_RECIPIENTS`
- **选填**（启用 AI）：`LLM_API_KEY`、`LLM_API_URL`、`LLM_MODEL`
- 其余为路径、项目名、日报/计划表结构相关的适配项，一般用默认值即可

> 仓库内**不含任何密钥与真实路径**，全部通过环境变量注入。未配置 SMTP 时程序只生成报表、不发邮件；未配置 `LLM_API_KEY` 时自动关闭大模型、回退规则分析。

### 3. 运行命令行版

```bash
python schedule_warning.py
```

Windows 也可直接双击 `run_warning.bat`。运行后：
- 报表输出到 `warning_output/工期预警报表_<日期>.xlsx`
- 配置了邮件则自动推送
- 设 `DUMP_HTML=1` 可额外导出邮件 HTML 预览到 `warning_output/`

### 4. 运行 Web 版

```bash
cd web
python app.py
```

或双击 `web/run_web.bat`，然后浏览器访问 <http://127.0.0.1:8080>，按页面提示上传进度计划与日报即可。

## 输入表格格式约定

### 日报（`daily_reports/*.xlsx`）

- 工作表名默认 `进行台账`（可用 `DAILY_SHEET_NAME` 覆盖，找不到时回退第一个工作表）
- 以 B 列 = `序号` 的行作为表头；按 `1.1 / 1.2 …` 分节
- 主要列（命令行版 `parse_daily` 约定）：

  | 列 | 字段 |
  |----|------|
  | E | 任务名称 |
  | F | 总量 |
  | G | 单位 |
  | H / I | 计划开始 / 计划完成 |
  | J / K | 实际开始 / 实际完成 |
  | L | 状态 |
  | O | 完成百分比 |
  | P | 备注 |

### 总进度计划（`master_plan/*.xlsx`）

命令行版 `load_plan` 自适应两种布局：

- **新版**：前 8 行内含表头，且有「任务名称」+「开始时间/完成时间」列；层级由任务名单元格缩进推断（indent 0→L1，1→L2…）。工作表名可用 `PLAN_SHEET_NAMES` 指定，否则取第一个工作表。
- **旧版**：任务名=第 5 列、层级=第 2 列、工期=第 6 列、开始=第 7 列、完成=第 8 列。

### 关键节点（`key_nodes/*.xlsx`，可选）

取第一个工作表，从第 2 行开始：第 2 列=节点名称，第 3 列=时间，第 4 列=类别。

## 大模型（LLM）配置

命令行版通过 OpenAI 兼容的 `chat/completions` 接口调用大模型，兼容 DeepSeek / 通义千问 / 智谱 / Kimi 及各类内部网关：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `LLM_API_URL` | `https://api.deepseek.com/v1/chat/completions` | 接口地址 |
| `LLM_API_KEY` | 空（关闭大模型） | API 密钥，**留空即回退规则分析** |
| `LLM_MODEL` | `deepseek-chat` | 模型名，建议用非推理模型 |

> 建议用**非推理模型**：推理模型的思考 token 不可控，容易耗尽 `LLM_MAX_TOKENS` 额度导致正文为空。相关超时、token 上限、温度等参数见 `schedule_warning.py` 配置区。

## 命令行版 vs Web 版

| | 命令行版 `schedule_warning.py` | Web 版 `web/` |
|---|---|---|
| 大模型 AI 分析 | ✅ 支持 | ❌ 纯规则分析 |
| 交互方式 | 命令行 / 定时任务 | 浏览器上传 |
| 主任务匹配 | 动态解析日报分节 | 基于 `MAPPING` 固定行号配置 |
| 适用场景 | 自动化、每日定时推送 | 人工临时比对、演示 |

> Web 版的 `schedule_warning_core.py` 采用基于固定行号的 `MAPPING` 配置，适配特定日报模板；命令行版更通用。二次开发时以命令行版为主。

## 安全说明

- 本仓库不含任何 API Key、邮箱密码、真实项目名或本地路径，全部经环境变量注入。
- `.env` 已在 `.gitignore` 中忽略，**请勿提交任何含密钥的文件**。
- Web 版默认仅监听 `127.0.0.1`。如需暴露到公网，请务必收紧 CORS 白名单并加上鉴权，否则任何人都能上传文件并触发邮件发送。
- 邮箱 `SMTP_PASS` 请使用邮箱服务商提供的**授权码**（163/QQ/126 等需在邮箱设置中单独申请），而非登录密码。
